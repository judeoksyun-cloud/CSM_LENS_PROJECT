# 보험업계 CSM 경영 대시보드 PRD

작성일: 2026-06-09

## 문서 역할

이 문서는 CSM 대시보드의 제품 배경, 사용자, 문제 정의, 기능 요구사항을 설명하는 초기 PRD다. 실제 시스템 설계, 에이전트 구성, 데이터 계약, 최신 데이터 기준, Movement 표준, LLM 사용 원칙은 [agent-architecture.md](../../agent-architecture.md)를 기준 문서로 사용한다. 실행과 재생성 절차는 [csm-agent-runbook.md](../../csm-agent-runbook.md)를 참고한다.

따라서 이 PRD에는 제품 요구사항과 사용자 시나리오를 남기고, 운영 중 변경될 가능성이 높은 상세 기준은 중복 관리하지 않는다.

## 1. 제품 개요

보험업계 CSM 경영 대시보드는 Open DART API로 보험사의 정기보고서와 XBRL 재무정보를 수집하고, IFRS17 관련 CSM 공시 정보를 파싱해 계리팀과 경영진이 분기 단위로 보험계약서비스마진의 규모, 변동, 업권 비교를 빠르게 파악하도록 돕는 분석 시스템이다.

첫 버전은 회사 내부 계리 산출 시스템을 대체하지 않는다. 공개 공시자료 기반의 외부 벤치마킹과 경영 보고용 요약을 제공하는 것이 목적이다.

## 2. 배경과 문제

IFRS17 도입 이후 CSM은 보험사의 미래 이익 체력과 수익 인식 구조를 설명하는 핵심 지표가 되었다. 그러나 보험사별 공시 양식, 주석 명칭, 표 구조, 세부 항목 표현이 달라 분기별 비교와 변동 원인 파악에 시간이 많이 든다.

계리팀은 분기 결산 시 다음과 같은 반복 업무를 수행한다.

- 보험사별 사업보고서, 반기보고서, 분기보고서를 찾는다.
- IFRS17 보험계약 관련 주석에서 CSM, 보험계약부채, 손실요소, 보험수익 관련 표를 찾는다.
- 회사별 표 구조와 단위를 맞춘다.
- 전분기 대비 변동과 업권 내 상대 위치를 설명할 수 있는 형태로 재가공한다.
- 임원 보고용 요약 테이블과 시각화에 맞춰 자료를 재편집한다.

이 시스템은 이 반복 업무를 API 수집, 파싱, 정규화, 대시보드 표시, 검증 로그까지 하나의 흐름으로 묶는다.

## 3. 목표

### 3.1 제품 목표

- 분기별 공개 공시자료 기반으로 보험사 CSM 잔액과 주요 변동 정보를 수집한다.
- 생명보험과 손해보험을 모두 포괄하는 공통 지표 체계를 제공한다.
- 경영진 보고에 적합한 요약 화면을 제공한다.
- 원문 공시와 파싱 결과를 연결해 수치 추적성과 검증 가능성을 확보한다.

### 3.2 성공 지표

- 지정 보험사 목록 기준 분기 공시 수집 성공률 95% 이상
- CSM 핵심 표 자동 탐지 성공률 80% 이상
- 자동 파싱 결과 중 수작업 보정 없이 사용 가능한 핵심 KPI 비율 70% 이상
- 분기 보고 자료 초안 작성 소요시간 50% 이상 감소
- 모든 대시보드 수치에 원문 공시 링크, 접수번호, 보고서명, 파싱 위치가 남아 있을 것

## 4. 대상 사용자

### 4.1 1차 사용자

- 계리팀 실무자: 공시자료 수집, 파싱 결과 검토, 수치 보정, 보고자료 생성
- 계리팀 리더: 보험사별 CSM 추이와 주요 변동 요인 검토

### 4.2 2차 사용자

- CFO/경영기획/리스크관리 담당자: 업권 내 상대 위치와 분기별 CSM 흐름 확인
- 임원 보고 담당자: 대시보드 화면과 요약 표를 기반으로 보고자료 작성

## 5. 범위

### 5.1 포함 범위

- Open DART API 인증키 기반 데이터 수집
- 보험사 고유번호 및 종목코드 관리
- 정기보고서 검색: 사업보고서, 반기보고서, 1분기보고서, 3분기보고서
- 공시 원문 ZIP/XML 다운로드
- XBRL 재무제표 원문 및 전체 재무제표 API 조회
- CSM 관련 주석 표 탐지 및 파싱
- 회사, 업권, 보고기간, 연결/별도, 단위 기준 정규화
- CSM 핵심 KPI 대시보드
- 파싱 신뢰도, 원문 링크, 수작업 보정 이력 관리

### 5.2 제외 범위

- 회사 내부 계리 모델 산출
- 계약 단위 또는 포트폴리오 단위 CSM 재계산
- 비공개 내부 데이터 연동
- 회계 전표 생성
- IFRS17 정책 판단 자동화
- 투자 의사결정 추천

## 6. Open DART 데이터 전제

공식 Open DART 문서 기준으로 다음 API를 사용한다.

| 용도 | API | 사용 이유 |
| --- | --- | --- |
| 회사 마스터 확보 | `corpCode.xml` | 공시대상회사의 고유번호, 회사명, 종목코드, 최종변경일자를 확보한다. |
| 정기보고서 검색 | `list.json` | 회사, 기간, 공시유형, 공시상세유형으로 사업/반기/분기보고서 접수번호를 찾는다. |
| 공시 원문 확보 | `document.xml` | 접수번호 기준 공시 원문 ZIP/XML을 내려받아 주석 표를 파싱한다. |
| 전체 재무제표 조회 | `fnlttSinglAcntAll.json` | 회사, 사업연도, 보고서 코드, 연결/별도 기준 전체 XBRL 계정과목을 조회한다. |
| XBRL 원문 확보 | `fnlttXbrl.xml` | 접수번호와 보고서 코드 기준 XBRL 재무제표 원문을 내려받아 구조화 데이터 파싱을 보강한다. |

보고서 코드는 다음 기준을 사용한다.

| 보고서 | 코드 |
| --- | --- |
| 1분기보고서 | `11013` |
| 반기보고서 | `11012` |
| 3분기보고서 | `11014` |
| 사업보고서 | `11011` |

Open DART는 재무정보의 정확성과 완전성을 보장하지 않으며, 정정공시가 있으면 수치가 바뀔 수 있다. 따라서 시스템은 최신 보고서 여부, 정정 여부, 접수번호, 수집 시점, 원문 링크를 항상 보존해야 한다.

### 6.1 데이터 기준

핵심 지표의 최신 기준은 [agent-architecture.md](../../agent-architecture.md)의 `데이터 기준`과 `CSM Movement 표준`을 따른다.

PRD 관점에서 유지할 원칙은 다음과 같다.

- 모든 수치는 원문 출처, 보고기간, 단위, 연결/별도 기준, 재보험 포함/제외 여부를 추적할 수 있어야 한다.
- 보유 CSM, 손익, K-ICS는 기준이 다를 수 있으므로 화면과 보고서에 기준을 함께 표시해야 한다.
- Movement 항목은 회사별 원문 항목명을 보존하면서 표준 항목으로 매핑해야 한다.
- 계산값과 표시값이 다르면 `검토필요` 상태를 남겨야 한다.

## 7. 핵심 사용자 시나리오

### 7.1 분기 CSM 요약

계리팀 리더는 2026년 1분기 기준 생보/손보 주요 보험사 CSM 잔액, 전기 대비 증감률, 보험수익 대비 CSM 규모를 한 화면에서 확인한다.

### 7.2 회사별 CSM 롤포워드 확인

계리 실무자는 특정 보험사를 선택해 기초 CSM, 신계약, 이자부리, 가정변경, 경험조정, 서비스 제공에 따른 인식, 기타 변동, 기말 CSM의 표준 롤포워드 항목을 확인한다.

### 7.3 업권 벤치마킹

경영기획 담당자는 생보와 손보를 나눠 CSM 규모 상위 회사, 전분기 증감률, CSM 대비 보험수익 비율, 순이익 대비 CSM 인식 규모를 비교한다.

### 7.4 파싱 결과 검증

계리 실무자는 자동 파싱된 CSM 숫자를 클릭해 원문 공시의 표 위치, 추출된 셀, 단위, 변환 로직, 신뢰도 점수를 확인하고 필요 시 보정값을 입력한다.

## 8. 주요 기능 요구사항

### 8.1 회사 마스터 관리

- 시스템은 Open DART `corpCode.xml`을 주기적으로 다운로드해 회사 마스터를 갱신해야 한다.
- 사용자는 분석 대상 보험사 목록을 관리할 수 있어야 한다.
- 회사별 업권 구분을 `생명보험`, `손해보험`, `재보험`, `기타`로 관리해야 한다.
- 상장사 종목코드가 없는 주요 비상장 보험사도 고유번호 기준으로 관리할 수 있어야 한다.

### 8.2 공시 수집

- 시스템은 분기별 대상 기간을 입력받아 `list.json`으로 정기보고서를 검색해야 한다.
- `pblntf_ty=A`와 보고서 상세유형을 활용해 사업보고서, 반기보고서, 분기보고서를 필터링해야 한다.
- 정정공시가 존재할 경우 최종보고서 우선 원칙을 적용하고, 정정 이력을 별도 표시해야 한다.
- 각 공시의 `rcept_no`, `report_nm`, `rcept_dt`, `corp_code`, `corp_name`, `stock_code`, `corp_cls`를 저장해야 한다.

### 8.3 원문 및 XBRL 수집

- 시스템은 `document.xml`로 공시 원문 파일을 내려받아 원문 저장소에 보관해야 한다.
- 시스템은 `fnlttXbrl.xml`로 XBRL 재무제표 원문을 내려받아 구조화 파싱에 활용해야 한다.
- 시스템은 `fnlttSinglAcntAll.json`으로 전체 재무제표 계정과목을 조회해 CSM 관련 재무제표 계정과 주석 파싱 결과를 대조해야 한다.
- 연결재무제표와 별도재무제표를 구분해 저장해야 한다.

### 8.4 CSM 주석 탐지

- 시스템은 원문 공시와 XBRL 주석에서 다음 키워드군을 기준으로 후보 섹션을 탐지해야 한다.
  - `보험계약서비스마진`
  - `계약서비스마진`
  - `CSM`
  - `보험계약부채`
  - `보험수익`
  - `손실요소`
  - `잔여보장부채`
- 후보 섹션은 보고서, 주석명, 표 제목, XML 노드 경로, 원문 텍스트 주변부와 함께 저장해야 한다.
- 같은 회사의 이전 분기 표 구조를 학습해 반복 출현하는 CSM 표를 우선 탐지해야 한다.

### 8.5 CSM 표 파싱

- 시스템은 후보 표에서 행/열 헤더를 추출하고, 표 방향을 판별해야 한다.
- 시스템은 숫자 단위(`원`, `천원`, `백만원`, `억원`)와 부호 표기, 괄호 음수 표기를 표준화해야 한다.
- 시스템은 다음 표준 항목으로 매핑을 시도해야 한다.
  - 기초 CSM
  - 신계약 CSM
  - 이자부리
  - 가정변경 또는 미래서비스 관련 변동
  - 경험조정
  - 서비스 제공에 따른 CSM 인식
  - 환율 또는 기타 변동
  - 기말 CSM
  - 손실요소
  - 보험계약부채
- 자동 매핑이 불확실한 항목은 `unmapped`로 보관하고 사용자 검토 대상으로 표시해야 한다.

### 8.6 정규화 데이터 모델

시스템은 최소한 다음 논리 테이블을 제공해야 한다.

| 테이블 | 설명 |
| --- | --- |
| `companies` | DART 고유번호, 회사명, 종목코드, 업권, 분석 대상 여부 |
| `filings` | 보고서 접수번호, 보고서명, 기간, 정정 여부, 원문 링크 |
| `source_documents` | 원문 ZIP/XML/XBRL 파일 메타데이터와 저장 위치 |
| `parsed_sections` | CSM 후보 섹션, 주석명, 표 제목, 원문 위치 |
| `parsed_tables` | 표 구조, 행/열 헤더, 원본 셀 값 |
| `csm_metrics` | 표준화된 CSM KPI 값 |
| `metric_overrides` | 사용자 보정값, 사유, 작성자, 변경 시각 |
| `quality_checks` | 파싱 신뢰도, 검증 결과, 오류 메시지 |

### 8.7 대시보드 화면

첫 버전의 대시보드는 다음 화면으로 구성한다.

#### 8.7.1 Executive Summary

- 전체 보험사 CSM 총액
- 생보/손보별 CSM 총액
- 전분기 대비 증감률
- CSM 상위 10개 보험사
- 증감률 상위/하위 보험사
- 데이터 수집 완료율과 파싱 검증 상태

#### 8.7.2 Company Detail

- 회사별 CSM 잔액 추이
- 보고서별 원문 링크
- CSM 롤포워드 표준 항목
- 원천 재무제표 기준 표시 및 선택
- 원문 추출 위치 및 신뢰도

#### 8.7.3 Peer Comparison

- 업권별 보험사 비교
- CSM 잔액, 증감률, 보험수익, 순이익 등 주요 지표 비교
- 회사 규모를 고려한 상대 지표
- 분기별 랭킹 변화

#### 8.7.4 AI Copilot

- 최신 검증 스냅샷을 기준으로 이상변화 감지, CSM Movement 원인분해, Peer 비교, 임원용 요약, 자연어 질의응답을 제공해야 한다.
- AI 답변은 근거, 계산식, 검증상태, 기준 기간을 함께 노출해야 한다.
- 샘플 데이터와 실제 데이터를 섞지 않고, 최신 검증 기간 외의 전망은 기본 노출하지 않아야 한다.
- 투자 추천이나 일반 목적 채팅은 제공하지 않아야 한다.

#### 8.7.5 Data Quality

- 수집 성공/실패 현황
- 파싱 성공/검토필요/실패 현황
- 정정공시 반영 여부
- 수작업 보정 내역
- 원문 대비 검증 로그

### 8.8 수작업 보정

- 사용자는 자동 파싱값을 보정할 수 있어야 한다.
- 보정값은 원본값을 덮어쓰지 않고 별도 컬럼으로 저장해야 한다.
- 대시보드는 기본적으로 최종 사용값을 표시하되, 원본값과 보정값의 차이를 추적할 수 있어야 한다.
- 모든 보정에는 사유 입력이 필요하다.

### 8.9 보고 자료 출력

- 사용자는 Executive Summary와 Peer Comparison의 핵심 표를 CSV 또는 Excel로 내보낼 수 있어야 한다.
- 사용자는 각 KPI의 원문 공시 링크가 포함된 검증용 CSV를 내려받을 수 있어야 한다.
- 첫 버전에서는 PowerPoint 자동 생성은 제외한다.

## 9. 비기능 요구사항

### 9.1 추적성

모든 KPI는 다음 정보를 거슬러 올라갈 수 있어야 한다.

- 회사
- 보고서명
- 접수번호
- 접수일자
- 수집 시각
- 원문 파일
- 원문 표 또는 XBRL 노드 위치
- 단위 변환 로직
- 자동 파싱값
- 사용자 보정값

### 9.2 신뢰도

- 자동 추출값에는 신뢰도 등급을 부여한다.
- 신뢰도 기준은 표 제목 일치, 키워드 밀도, 전분기 구조 유사도, 숫자 합계 검증, 계정 대조 결과를 조합한다.
- 신뢰도 낮음 항목은 경영 대시보드 집계에 포함하되 `검토필요` 배지를 표시한다.

### 9.3 성능

- 대상 보험사 50개, 최근 12개 분기 기준 대시보드 초기 조회는 5초 이내를 목표로 한다.
- 전체 수집 및 파싱 배치는 대상 보험사 50개, 1개 분기 기준 30분 이내 완료를 목표로 한다.

### 9.4 보안

- Open DART API 인증키는 환경변수 또는 비밀 저장소에 보관한다.
- 사용자의 보정 이력과 다운로드 로그를 남긴다.
- 공개 공시자료 기반이므로 민감 계약 정보는 저장하지 않는다.

### 9.5 운영 안정성

- Open DART 요청 제한 오류, 시스템 점검, 파일 없음, 조회 데이터 없음 상태를 구분해 처리한다.
- 실패한 수집 작업은 재시도 가능해야 한다.
- 정정공시가 새로 감지되면 기존 데이터와 새 데이터의 차이를 표시해야 한다.

## 10. 파싱 접근법

### 10.1 접근안 A: 원문 주석 중심

`document.xml`로 받은 공시 원문에서 CSM 관련 주석과 표를 직접 파싱한다.

장점:
- 공시에서 사람이 보는 CSM 표를 가장 직접적으로 재현할 수 있다.
- CSM처럼 주석 중심으로 공시되는 항목에 강하다.

단점:
- 회사별 표 구조 차이에 취약하다.
- HTML/XML 표 파싱과 헤더 해석 규칙이 복잡하다.

### 10.2 접근안 B: XBRL 중심

`fnlttXbrl.xml`과 `fnlttSinglAcntAll.json` 중심으로 구조화 재무정보를 추출한다.

장점:
- 계정과목과 재무제표 구조가 비교적 안정적이다.
- 연결/별도, 사업연도, 보고서 코드 기준 정규화가 쉽다.

단점:
- CSM 세부 롤포워드는 표준 계정 API만으로 충분하지 않을 수 있다.
- 주석성 텍스트와 회사별 세부 표를 놓칠 수 있다.

### 10.3 권장 접근안: 하이브리드

첫 버전은 하이브리드 접근을 채택한다.

- `list.json`으로 보고서와 접수번호를 찾는다.
- `document.xml`로 CSM 주석 표를 탐지하고 파싱한다.
- `fnlttXbrl.xml`과 `fnlttSinglAcntAll.json`으로 재무제표 계정과 보고서 기준 정보를 보강한다.
- 자동 파싱값은 항상 원문 위치와 함께 저장한다.
- 불확실한 항목은 수작업 보정 워크플로우로 넘긴다.

이 방식은 경영 대시보드에 필요한 CSM 주석 정보를 놓치지 않으면서, XBRL 기반의 정합성 검증도 함께 가져갈 수 있다.

## 11. 품질 검증 규칙

상세 검증 기준과 에이전트/스킬별 역할은 [agent-architecture.md](../../agent-architecture.md) 및 사용자 스킬인 `csm-data-validation`, `csm-movement-mapping`을 따른다. 이 PRD에서는 제품 요구사항 수준의 검증 원칙만 유지한다.

- 기초 CSM + 주요 변동 항목의 합이 기말 CSM과 크게 다르면 검토필요로 표시한다.
- 원문 표 단위와 대시보드 단위가 다르면 변환 로그를 남긴다.
- 동일 회사의 전분기 표 구조와 크게 다르면 검토필요로 표시한다.
- 정정공시가 존재하면 기존 수치와 정정 후 수치를 비교한다.
- 연결재무제표와 별도재무제표가 혼재되면 집계에서 제외하고 경고한다.

## 12. MVP 범위

이 절의 MVP 범위는 초기 제품 요구사항 기준이다. 현재 프로토타입 상태, 에이전트 구성, 실제 구현 우선순위는 [agent-architecture.md](../../agent-architecture.md)를 우선한다.

MVP는 다음을 포함한다.

- 보험사 마스터 수동 등록 및 DART 고유번호 매핑
- 지정 분기 정기보고서 수집
- 원문 문서와 XBRL 파일 다운로드
- CSM 후보 표 자동 탐지
- CSM 잔액, 전분기 증감, 회사별 원문 링크 제공
- Executive Summary, Company Detail, Data Quality 화면
- CSV 내보내기
- 수작업 보정 이력

MVP에서 제외한다.

- 자동 PowerPoint 생성
- 자연어 질의 응답
- 내부 계리 시스템 연동
- 계리 가정 시나리오 분석
- CSM 미래 예측

## 13. 릴리스 단계

### 13.1 Phase 1: 수집과 원문 추적

- DART 회사 마스터 적재

### 13.3 Phase 3: 경영 대시보드

- Executive Summary
- Company Detail
- Peer Comparison
- Data Quality

- 회사별 표 구조 학습
- 정정공시 자동 비교

- 대상 보험사 초기 목록
- 생보/손보 업권 구분 기준
- CSM 표준 롤포워드 항목의 최종 명칭
- 경영 보고용 단위: 억원 또는 십억원
- 대시보드 제공 방식: 웹앱, 내부 BI, 파일 기반 리포트

## 16. 인수 기준

- 사용자는 특정 분기와 보험사 목록을 지정해 공시 수집을 실행할 수 있다.
- 시스템은 대상 회사별 최신 정기보고서 접수번호와 원문 링크를 저장한다.
- 시스템은 CSM 후보 주석 표를 자동으로 식별하고 신뢰도 등급을 부여한다.
- Executive Summary에서 업권별 CSM 총액과 회사별 순위를 볼 수 있다.
- Company Detail에서 회사별 CSM 원문 위치와 파싱값을 검증할 수 있다.
- 사용자는 파싱값을 보정하고 보정 이력을 확인할 수 있다.
- 사용자는 대시보드 핵심 데이터를 CSV로 내보낼 수 있다.
