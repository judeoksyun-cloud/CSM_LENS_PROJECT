# Open DART 기반 IFRS17 CSM 분석 Agent

| 항목 | 내용 |
| --- | --- |
| 문제 정의 | As-Is에서는 리더·임원이 CSM 현황이나 Peer 비교를 요청할 때마다 실무자가 공시 탐색, 표 해석, 기준 정리, 엑셀 재가공, 보고자료 편집을 반복한다. 질문이 들어오거나 정정공시가 생기면 원문과 엑셀을 다시 오가며 재확인해야 하고, 검증 근거가 개인 파일과 기억에 흩어진다. 2025 Q4 Open DART 검산 스냅샷 기준 삼성생명은 보유 CSM 13.2조원, 보험손익 1.0조원, 투자손익 2.0조원, K-ICS 198.0%이고, 삼성화재는 보유 CSM 14.2조원, 보험손익 1.4조원, 투자손익 1.3조원, K-ICS 262.87%다. 이런 핵심 숫자도 출처·기준·검산 상태가 함께 묶이지 않으면 비교와 보고 대응이 반복 재작업이 된다. |
| 대상 사용자 / JTBD | 1차 사용자는 계리팀 실무자다. 회사와 분기를 선택하면 CSM 표 후보, Movement 매핑, 손익/K-ICS 기준, 검산 결과를 한 흐름에서 확인하고 싶다. 2차 사용자는 계리 리더, 경영기획, CFO 조직이다. 검산된 스냅샷으로 보유 CSM·손익·K-ICS와 시장 비교, 전망, AI 해설을 즉시 확인해 회의 질문과 보고 메시지를 준비하고 싶다. |
| 핵심 기능 1 | To-Be 파이프라인: 회사·기간 선택 -> Open DART 수집 -> CSM 후보 표 탐지 -> Movement 표준 매핑 -> 손익/K-ICS 기준 정규화 -> 검산 규칙 적용 -> Human Review 큐 분리 -> 검증 스냅샷 생성을 목표 흐름으로 둔다. 현재 Agent Run은 적재 스냅샷 재검산 모드로 제공한다. |
| 핵심 기능 2 | 검산된 최신 스냅샷을 대시보드, Peer 비교, 전망, AI 요약으로 연결한다. AI 응답은 보고 문장 초안 역할에 머물고, 근거 공시, 계산식, 기준 기간, 검증 상태를 함께 표시한다. |
| 안 만들 것 | 내부 계리 모델 대체, 계약 단위 CSM 재계산, 비공개 내부 데이터 연동, 회계 정책/IFRS17 판단 자동화, 투자 추천, 사람 승인 없는 보정 반영, 고객·계약 단위 자동 의사결정은 만들지 않는다. 이유는 이 파일럿의 목적이 최종 판단 자동화가 아니라 사람 판단 전 수집·검산·요약 단계를 줄이는 것이기 때문이다. |
| 입력 데이터 | Open DART API 기반 공개 공시만 사용한다. 파일럿 대상은 삼성생명·삼성화재, 기간은 2025 Q1~Q4다. 핵심 기준은 별도재무제표·재보험 제외 보유 CSM, 별도 보험서비스손익, 별도 투자손익 + 영업외손익 + 연결효과, 지배주주 연결순이익, 지급여력 공시 K-ICS다. |
| 출력 형식 | CSM Lens 대시보드, Agent Timeline, Data Quality 패널, AI 요약 카드, Human Review 큐, 검산 로그 JSON, 원문 접수번호·보고서명·표 번호가 연결된 검증 메타데이터를 출력한다. |
| 사람 승인 지점 | 검산 실패, 출처 누락, 단위/기준 불일치, Movement 항목 매핑 불확실, 수작업 보정 반영 전에는 Human Review 큐로 보낸다. 휴먼리뷰는 자동 완료하지 않고 검토 필요 또는 검토 없음 상태로 끝낸다. |
| 완료 정의 | 삼성생명·삼성화재 2025 Q1~Q4 Open DART 스냅샷에서 CSM Movement 합계와 기말 CSM이 검산되고, 2025 Q4 대표 지표가 대시보드에 표시되며, 검토필요/실패/통과 상태가 Data Quality와 Agent Timeline에 남는다. As-Is의 반복 작업인 공시 탐색, 표 구조 확인, 기준 정리, Peer 비교표 재작성, 보고 요약 초안 작성이 To-Be 화면에서 한 흐름으로 재현되어야 한다. 더미값과 실제값은 분리 표시되고, AI 요약은 최신 검증 기간과 근거·계산식·검증 상태를 함께 출력한다. |
| D5 인계 메모 | 입력은 Open DART 추출 JSON과 수동 리뷰 오버라이드 파일, 현재 런타임 처리는 적재 원문 확인 -> 파싱 스냅샷 확인 -> Movement 계약 매핑 -> 스냅샷 재검산 -> 휴먼리뷰 순서다. 출력은 `dashboard-data.generated.js`, 대시보드 화면, AI 요약이며, 레거시 `csm-dashboard-agent-output.json`은 2개사 파일럿 보존물이다. |

## 검증 질문 5개

1. 가장 약한 가정은 무엇인가? 삼성생명·삼성화재에서 확인한 CSM 표 구조와 Movement 항목 매핑이 다른 보험사와 다음 분기에도 반복 가능하다는 가정이다.
2. 데이터 부족 위험은 무엇인가? Open DART 원문 표에서 단위, 재보험 제외 여부, 별도/연결 기준이 명확하지 않으면 자동 확정하지 않고 검토 필요로 남겨야 한다.
3. 보안 위험은 무엇인가? 공개 공시 기반 파일럿이므로 비공개 내부 데이터, 고객/계약 정보, 로컬 PDF 업로드 자료는 AI 게이트웨이에 넣지 않는다.
4. 비용 위험은 무엇인가? LLM은 표 의미 해석과 보고 문장 초안에만 제한하고, 숫자 수집·계산·검산은 결정론적 워커가 수행해 반복 호출 비용을 줄인다.
5. 사람 승인 지점은 어디인가? 수작업 보정, 검산 실패, 매핑 불확실, 정정공시 반영, 보고 전 AI 요약 사용 단계에서 계리 실무자 확인을 요구한다.
